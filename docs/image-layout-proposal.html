方案 A · 图片独立成行 + 统一宽度策略 推荐

单图 + 上下文文字

这是生成的对比图：

可以看到曲线在 t=2s 后趋于平稳。

图片独立成行，宽度统一为气泡宽的 85%，上下各留 8dp。

连续多图 → 纵向等宽序列

共三张：

统一宽度纵向堆叠，4dp 间距，节奏一致。

小图（图标/截图局部）

按钮样式如下：

intrinsic ≤ 160dp 的小图保持原尺寸、左对齐，不放大。
  1. 图片一律独立成行（block 级），不再与文字 FlowRow 混排；段落内图片前后的文字各成一段。
  2. 宽度策略：intrinsic 宽 ≤ 160dp → 原尺寸；否则统一 min(气泡宽 × 0.85, intrinsic)，高度按比例。
  3. 圆角统一 8dp、图间距 4dp、图文间距 8dp；连续多图自然纵向堆叠。
  4. 改动集中在 MarkdownNew / Markdown 图片渲染处，行为可预期，风险小。

方案 B · 连续多图两列网格 可选增强

多图 2 列网格（微信九宫格风格）

共四张：

省空间、整齐；但单张大图也会被压成半宽格子，会牺牲大图细节（点击可放大弥补）。

混合：单图走方案 A，≥2 张才进网格

第一张单独展示：

其余两张：

逻辑略复杂：需要跨块合并连续图片（AST 后处理），改动面更大。
  1. 仅当连续 ≥2 张图片时进 2 列网格，单图仍按方案 A。
  2. 需要把相邻 image 块合并成组（MarkdownNew 块级预处理），实现成本中等。

方案 C · 全部满宽 不推荐，仅对比

所有图片 fillMaxWidth

按钮样式如下：

最整齐，但小图标被放大到满宽，模糊且喧宾夺主；表情/签名档类小图体验差。

结论建议

先落 方案 A（独立成行 + 统一宽度 + 间距节奏），解决 90% 的「乱」； 网格（方案 B）作为后续增强可叠加，不影响 A 的规则。gif 动图、尺寸预占、失败重试等既有能力不受影响。
