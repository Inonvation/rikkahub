拍照搜题 · 交互与排版重构方案

099 · 2026-09-07 · 基于真机反馈：思考过程折叠态不可见 + 整页排版层次不清

一、现状问题

  • 思考过程折叠后完全不可见——流式思考期间用户什么都看不到，只能点开才能确认"它在动"。聊天界面的做法是：折叠态仍露出末尾最新内容，旧的自动折叠。
  • 排版输入区（图片卡 + 补充说明 + 按钮）永远占据上半屏，解题完成后输出被挤到屏幕下方，要滚很久才能看到结果。
  • 排版解题完成后输入区仍保持"待输入"的大块形态，与当前任务（阅读结果）不匹配，视觉重心错位。
  • 解答卡生成中默认折叠——用户必须手动点开才能看到流式进度，与"实时流式输出"的产品预期矛盾。

二、设计原则（输出语义的三层结构）

  • 思考过程 = 过程流：模型的实时思考，属于"幕后直播"。默认只露尾部（最新），点击展开看全量。形态参照聊天界面思考条。
  • 解答 = 过程 + 作答一体：解题过程（详细推导，便于理解）与精炼作答（可誊抄）是同一份解答的两个层次，合并在一张卡内，上下相邻，用小节标签与高亮底色区分。
  • 页面随任务切换重心：没解题时输入区是主角；解题中/完成后输出区是主角，输入收缩成一条摘要。空间让给用户真正要看的东西。

四、重点细节 1：思考过程「折叠露出尾部」

对齐聊天界面思考条的行为：折叠 ≠ 隐藏，而是"顶部旧的收起、底部最新的始终可见"。流式期间无需任何操作就能看到它正在工作。

折叠态（默认）live

……先设斜面倾角为 θ，对物块进行受力分解……
……摩擦力 f = μN，N = mg·cosθ……
……沿斜面方向列牛顿第二定律：mg·sinθ − f = ma，
……代入数据解得 a ≈ 3.2 m/s²，接下来验证……
✓ 固定预览高度（约 64dp），只渲染文本末尾；顶部渐隐遮罩提示"上面还有更多"；思考中带脉冲圆点 + “思考中”角标。

展开态点击切换

题目要求求加速度 a。已知 μ=0.25，θ=30°，g 取 9.8……
先设斜面倾角为 θ，对物块进行受力分解……
摩擦力 f = μN，N = mg·cosθ……
沿斜面方向列牛顿第二定律：mg·sinθ − f = ma，
代入数据解得 a ≈ 3.2 m/s²，接下来验证单位与合理性……
✓ 全量内容；流式更新时自动跟随底部（用户上滚阅读则暂停跟随，滚回底部附近恢复）。再次点击收起回预览态。

实现要点：预览区用 heightIn(max = 64.dp) + 反向内容对齐（verticalArrangement = Arrangement.Bottom 或测量后滚动到底），顶部叠加渐隐 Bruh 遮罩；思考生成中的圆点复用现有动画。

五、重点细节 2：解答卡与操作条

项行为
解答卡默认状态生成中自动展开并跟随底部（修正"默认折叠看不到流式"）；完成后保持展开，用户可手动收起；历史回看时默认展开（结果优先）。
卡内结构保持：小节标签「解题过程」→ Markdown 流式 → 高亮子块「作答 · 可直接誊抄」（独立复制按钮）。作答子块首次出现时若视口不在底部，轻滚动一次到可见。
底部操作条（结果态）复制作答（主按钮，直接复制精炼作答全文）+ 重新解题（用当前图重跑）。仅在有结果时出现，生成中隐藏（由"停止生成"替代）。
题图摘要条（生成/结果态）小缩略图 + 时间/状态 + 重新裁剪、移除图标按钮；点击缩略图打开全屏缩放预览（复用 ZoomableAsyncImage）。
状态切换动画输入区大卡 ↔ 摘要条用 AnimatedContent 过渡，避免布局跳变；输出区从底部淡入。

六、改动清单与边界

改

  • SolvePage.kt：页面按 输入/生成/结果 三态重排（AnimatedContent 切换输入区两种形态）；新增题图摘要条与底部操作条；思考条折叠露出尾部（预览高度 + 渐隐 + 思考中角标）；解答卡生成中自动展开跟随、作答子块出现时轻滚动。
  • strings.xml（EN/zh）：新增 思考中 / 复制作答 / 重新解题 / 点击放大核对 等文案。
  • 复用不动：SolutionCard 的过程+作答合并结构、跟随滚动策略（600px 阈值）、SplitSolveOutput 协议、前台保活、历史与 DAO。
