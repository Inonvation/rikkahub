# 拍照搜题 UI 重构方案

> 状态：**已实施（2026-09-07，P0–P3 全部落地，compileDebugKotlin ✅）**
> 范围：`SolvePage.kt` / `SolveCropOverlay.kt` / `SolveHistoryView.kt`（纯展示层）
> 约束：不动 `SolveVM`、不动 phase 状态机、不引入新依赖、不改裁剪/相机手势逻辑

## 实施记录

- **A（结果工作页）**：内容区全部去卡片——题图/题干/思考/解答/等待指示/模型未配置/空兜底均改为区块 + `SolveSectionDivider()`（outlineVariant 0.6 透明度）定界的文档流；每区块统一纵向 padding(≈10dp)；作答块改为通铺 `primaryContainer(0.45)` 圆角 8dp 浅色块（去圆角描边壳）；「解题过程」小节标签删除（区块头「解答」已表达）；删除吸顶冻结条（reasoning 窗口坐标追踪、`stickyVisible`、悬浮 ReasoningHeaderRow 全部移除，约 -70 行）；SolutionCard 折叠改为头部行 TextButton「展开/收起」（正文不再整卡可点、可自由拖选），生成中折叠仍显示「生成中…」；思考头部完成态右侧新增「查看全文」文本入口（新字符串 `photo_solve_view_reasoning`，default+zh）；复制作答从 16dp 裸图标改为作答块头部行「复制」TextButton（默认命中区）。
- **底部操作条**：改为 44dp 定高 + 分隔线顶线的单容器条件渲染——生成中居中「停止」胶囊、结果态双按钮；不再用 AnimatedVisibility 纵向叠放（该 Compose 版本 Box 内无扩展 + 切换时高度翻倍跳动），动画移除换取稳定性。
- **B（框选面板）**：面板顶部加分隔线与预览区隔开；提示/模型未配置错误互斥为单行（同占左区），右侧工具图标（重拍/相册）同排且恢复默认 48dp 命中区；补充说明输入（weight=1）+「解题」主按钮同排成主行。
- **C（取景页）**：首屏顶栏补标题「拍照搜题」（其余未动，相机交互非本次范围）。
- **D（历史列表）**：整行圆角卡 + 8dp 间距改为分隔线列表（`itemsIndexed`，index>0 行首分隔线、无拖尾线，inset 16dp）；滑删背景由圆角卡形改通铺 errorContainer；长按多选/左滑删除/勾选逻辑保留。
- 验证：`:app:compileDebugKotlin` ✅（首轮 2 错：CropOverlay TextAlign 残留引用 + Box 内无 AnimatedVisibility 扩展，均已修复）。


## 一、现状诊断

### 1.1 布局问题（结果/解题工作页 `SolveWorkScreen` 最重）

结果页由 4~5 张圆角带边框 Surface 纵向堆叠构成：

- `ImageThumbStrip`（题图条卡）→ `QuestionCard`（题干卡，条件出现）→ `ReasoningCard`（思考卡）→ `SolutionCard`（解答卡）→ `ModelNotConfiguredCard`（错误卡，条件出现）。
- 每张卡独立圆角 + 边框 + 内 padding（12~16dp），卡间再留 12dp 间距。视觉上是"一摞控件抽屉"，而不是"一份解答稿"。
- **卡中卡**：`SolutionCard` 内的"作答 · 可直接誊抄"又是一个 `primaryContainer` 圆角卡 + 描边，同一区块出现两级边框。
- 信息密度低：正文被卡片内边距持续收窄；`ReasoningCard` 完成后只余一行头部文字却仍占一整张卡；解题启动的等待指示独占一张空卡。

### 1.2 交互问题

1. **折叠命中区错误**（`SolutionCard`）：整个 Surface 挂 `clickable`，点正文任意处都折叠/展开；而正文包在 `SelectionContainer` 里——用户想拖选/长按选词时极易误触整卡折叠。折叠/展开是"标题行动作"，不该整卡可点。
2. **操作入口分散且命中区过小**：复制在作答子卡右上角 16dp 图标，且被 `LocalMinimumInteractiveComponentSize = 0` 缩小；换题在题图条尾部小图标；修正藏在题干卡头部文字按钮。同类"行内操作"没有一个统一落点。
3. **思考链路过绕**：`ReasoningCard`（卡）→ 吸顶冻结条（靠 `onLayoutRectChanged` + `boundsInWindow` 追踪窗口坐标，条件 `stickyVisible` 三段比较）→ `ModalBottomSheet` 全文弹窗。冻结条为"滚出视口后仍能打开思考"服务，但引入一套窗口坐标同步机制，旋转/分屏/动画期间易错位。
4. **底部栏形态跳变**：生成中 = 一整条全宽 `OutlinedButton`「停止」；结果态 = 两个按钮。两个 `AnimatedVisibility` 纵向滑入滑出，高度不一致导致底部内容跳动。
5. **框选确认页底部面板堆叠**（`SolveCropOverlay`）：一整块 Surface 面板里从上到下叠了 4 种不同性质元素——引导小字一行、模型未配置提示一行（仅未配置时）、单行输入（外层再嵌一层 Surface）、[重拍|相册] 两图标 + 解题按钮一行。图标无文字，可发现性差；输入框被"卡中卡"包裹。
6. **历史列表同为卡片列表**（`SolveHistoryView`）：整行圆角卡 + 8dp 间距，左滑删除背景也是圆角卡形，密度与风格与上面的问题一致。

### 1.3 结论

拍照搜题的产物本质是"一页解答稿"（题图 → 题干 → 思考 → 推导 → 作答），应像读文章一样自上而下流动。当前"每块一个容器"的表达把文档语义切碎。重构方向确定为：**内容区去卡片化，改为分隔线定界的文档流；操作收拢进各区块的头部行；折叠仅由头部行触发。**

## 二、重构目标与设计原则

- **文档流版式**：内容区无独立圆角卡。区块纵向排列，区块间以 `HorizontalDivider` 定界；间距用区块内 padding（约 10~12dp）统一，不再靠卡间距。
- **头部行 = 区块语义 + 操作位**：每区块第一行左侧为区块标签（如「题干」「解答」），右侧为该区块的操作（修正 / 查看全文 / 复制 / 展开收起 / 换题），操作落点可预期、命中区 ≥ 40dp（该处不再设 `MinimumInteractiveComponentSize = 0` 的 icon）。
- **卡片只留给高价值实体**：全页保留一个可强调的浅色块——"作答"内容块（`primaryContainer.copy(alpha≈0.45)`），但**去掉其圆角描边壳**，降级为整行通铺的浅色文档块，不再卡中卡。
- **正文随时可选中**：所有可折叠区块，折叠触发点只在其头部行；正文区不再被父级 clickable 拦截。

## 三、分块方案

### A. 结果/解题工作页 `SolveWorkScreen`（核心，P0）

#### A.1 页面骨架

```
Scaffold topBar（不变：标题 + 历史 + 模型）
└─ 内容区（verticalScroll，水平 padding 16dp，无间距排版）
   ├─ Section 题图
   ├─ Section 题干        （OCR 回填才有）
   ├─ Section 思考        （reasoning 非空才有）
   ├─ Section 解答        （process/finalAnswer 非空才有）
   ├─ 等待指示             （生成中且无产出时，内联一行，不再是卡）
   ├─ 模型未配置提示       （条件出现，错误色文字行，不再是卡）
   └─ 空产出兜底文字      （保留）
```

区块间规则：相邻 section 之间画 `HorizontalDivider(color = outlineVariant.copy(alpha≈0.6))`；末尾区块到页面底部不画。

#### A.2 各区块改造

| 现组件 | 改后形态 | 操作落点 |
|---|---|---|
| `ImageThumbStrip` | 「题图」区块：缩略图（40×52，点击全屏核对）+ 单行说明 | 头部行右侧：换题 |
| `QuestionCard` | 「题干」区块：头部行（题干 + 修正）+ 正文纯文本（可长按选择）；编辑态内联输入，保存/取消进头部行 | 头部行右侧：修正 → 保存/取消 |
| `ReasoningCard` | 「思考」区块：头部行（流式时"正在思考…"轮换 + 计时；完成态"思考了 n 秒"）+ 右侧「查看全文」；流式中预览体保持 100dp 内高贴底跟随，渐隐遮罩保留但底色改页面背景 | 头部行右侧：查看全文（打开既有 sheet） |
| `SolutionCard` | 「解答」区块：头部行（解答 + 展开/收起 + 复制作答）+ 正文 = 过程 markdown + 尾部"作答"通铺浅色块（去边框去圆角） | 头部行右侧：展开/收起、复制 |
| 等待指示 Surface | 内联行：`LinearWavyProgressIndicator` + 文案，无卡壳 | — |
| `ModelNotConfiguredCard` | 内联错误色文字行（`onErrorContainer`→`error` 文本 + 分隔线定界） | — |

#### A.3 交互修正

1. **折叠只挂头部行**：`SolutionCard` 的 `Modifier.clickable` 从整卡移到头部行（保留展开/收起文案切换）。正文 `SelectionContainer` 区域不再会被点按折叠。副作用：原来"点正文空白处折叠"的手势消失——按设计原则这是修正而非回归（折叠属于头部动作）。
2. **删除吸顶冻结条机制**：去掉 `reasoningCardTopY/BottomY/contentTopY` 的窗口坐标追踪、`stickyVisible` 及其悬浮 `Surface`。理由：流式期间思考预览 100dp 贴底跟随，用户视线始终停在最新内容，不需要"滚出视口仍可打开"的中间层；需要回看时经「思考」区块头部行的「查看全文」进 sheet。直接净删约 60 行同步逻辑，消除旋转/导航错位隐患。
3. **底部栏统一高度、避免跳变**：生成中/结果态用同一容器（固定内容高 + 导航条 padding），切换只换内容不换布局——生成中为居中「停止」胶囊按钮（非全宽），结果态保持「重新解题 + 再拍一题」双按钮。动画改为交叉淡入（原纵向滑入滑出保留也可，但容器高度恒定）。
4. **复制命中区恢复**：作答块头部行内放「复制」操作（`TextButton` 或 ≥40dp 图标按钮），不再用 16dp 裸图标 + 零最小尺寸。

### B. 框选确认页底部面板 `SolveCropOverlay`（P1）

1. 拆掉整块 `Surface` 面板与输入框的嵌套 `Surface`：面板改为普通底色块，顶部用一条 `HorizontalDivider` 与图片预览区隔开（呼应分隔线语言）。
2. 信息行合并：引导小字与"模型未配置"错误提示互斥占用同一行（默认引导文案，未配置时替换为错误文案），不再叠两行。
3. 操作行重组为两行、行内满载：
   - 主行（同排）：`补充说明输入框`（weight=1f，单行）+ `解题` 主按钮。唯一输入与唯一主操作同排，缩短操作路径。
   - 工具行：`重拍` / `相册` 两个图标按钮（保留 haptic 与语义，命中区 ≥40dp）。放主行下方或并入主行左侧均可，落地上以"不挤占输入"为准。
4. 底部 panel 的 padding 统一 16dp，去除内部重复圆角。

### C. 取景页 `SolveCameraView`（P3，低风险可选）

结构符合相机惯例，仅小修：

1. 取景第一屏顶栏补标题「拍照搜题」（现 `FloatingCameraTopBar` 仅在框选阶段传 title，取景阶段 title=null，左返回 + spacer 失衡）。
2. 变焦倍率 chip 与快门行间距从 `bottom = 120.dp` 收紧（适配新的底部栏参考线），避免左下角空旷。

### D. 历史列表 `SolveHistoryView`（P2）

1. 记录项从"圆角卡 + 8dp 间距"改为"分隔线列表行"：每行 padding 14~16dp，行间 `HorizontalDivider`，缩略图、题干、摘要布局不变（其行内已是高密度排布，无需重排）。
2. `SwipeToDismissBox` 的背景由圆角卡形改为通铺 `errorContainer`（圆角仅保留 4dp 以内或不保留），与列表语言一致。
3. 多选模式、悬浮工具条、长按/左滑语义全部保留。

## 四、不做的事（边界）

- 不改 `SolveVM.kt` / `SolvePhase` 流转 / 裁剪归一化换算 / 相机 bind 逻辑。
- 不重排取景 → 框选 → 自动解题的阶段顺序（框选确认即解题为既定闭环）。
- 不动思考全文弹窗（sheet）的内部结构，仅保留从新头部行打开它的入口。
- 不改历史记录的存取与回填逻辑（`restoreRecord`）。

## 六、取舍说明

1. **去卡片但不做纯"无边距纸面"**：题干/解答仍保留区块纵向呼吸感（区块内 padding），避免文档流变成密排表格；分隔线用低透明度 `outlineVariant`，弱于原卡片边框，视觉噪声不增反降。
2. **作答块保留浅色底、去掉边框壳**：保留"作答是最终答案"的强调语义（用户可一眼誊抄），去掉卡中卡的双边框视觉。
3. **思考完成态仍不预览正文**：思考全文通常很长且非解题必读，头部行（思考了 n 秒 + 查看全文）已是足够入口，保持现状语义、只去卡片壳。
